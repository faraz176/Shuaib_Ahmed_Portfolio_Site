Teaching through systems design · 164-slide guide

Minecraft CPU and Network Design

A build guide that moves from logic gates to frames, destination addresses, and error checks, with deliberately failing examples to show where a simple checksum breaks.

Design scope

Teach the abstraction by making every field visible.

The RedLink design uses three SOP-delimited nibbles: a destination, a payload, and a check value. In the worked frame, destination 2 is 0010, payload A is 1010, and check 8 is 1000 because 2 XOR A = 8.

Destination0010SOP = 1
Payload1010SOP = 0
XOR check10002 XOR A = 8

Guide reference: slides 121–124 for the frame concept and slides 134–135 for the sender/receiver example.

Healthy frame

The combined XOR returns zero.

2 XOR A XOR 8 = 0
0010 XOR 1010 XOR 1000 = 0000

When the destination matches and the combined XOR is zero, the receiver accepts payload A. That rule is small enough to build and trace, making it useful for teaching the receiver's decision rather than hiding it behind a library call.

Deliberate collision

Flip the same bit in two fields, and the checksum sees nothing.

Change payload A → B (1010 → 1011) and check 8 → 9 (1000 → 1001). Both changes flip the least-significant bit position. XORing the same error twice cancels its effect:

2 XOR B XOR 9 = 0
0010 XOR 1011 XOR 1001 = 0000

The receiver still sees zero and accepts corrupted payload B. This is the checksum collision exercise documented on slide 138.

Why the failure is useful

A valid-looking frame is not proof of message integrity.

The demonstration distinguishes error detection from a boolean "passed" indicator. A simple XOR can detect many accidental changes, but structured changes in multiple fields can cancel. The lesson carries directly into real network troubleshooting: validate the path, the payload, and the limits of the check instead of treating one green status as complete evidence.

Evidence boundary

This is a modeled design guide, not a claimed completed build.

The source contains 164 slides covering logic, CPU construction, packet parsing, addressed frames, bad-frame rejection, start-of-frame recovery, and checksum collisions. Logic and example programs were checked in a Python model. The guide assumes vanilla Java Edition in a Creative Superflat world; it does not establish that the complete design was built or timing-tested in-game. RedLink is a teaching abstraction, not Ethernet FCS, CRC, IP, TCP, encryption, authentication, or an interoperability implementation.
